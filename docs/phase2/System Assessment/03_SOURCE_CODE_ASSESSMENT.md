### 3.3. Code Complexity

Không có `cloc`, `scc`, `lizard` hoặc `ctags` trong môi trường; không cài thêm công cụ. Metric dưới đây do script chỉ đọc tính trên **141 body của method/constructor ở top-level type**:

- Method physical LOC: từ dòng declaration/annotation đầu tiên đến closing brace, inclusive.
- `Heuristic CC = 1 + branch points`.
- Branch points được đếm chính xác theo token sau khi bỏ string/char literal và line comment: `if`, `for`, `while`, `case`, `catch`, `&&`, `||`, toán tử ternary `?`.
- Không tính implicit branch, exception path, lambda iteration, abstract/interface method, compact record constructor, nested-type method hay code Lombok sinh ra. Vì không dùng Java AST, đây là **heuristic để xếp hạng điểm cần đọc**, không phải cyclomatic complexity chuẩn để đặt quality gate.

#### Dependency cycle được xác minh lại

- `RegisterService` và `LoginService` import/call `AccountRepository` (`RegisterService.java:7,14-18`; `LoginService.java:6,12-18`).
- `MySqlAccountRepository` implements `AccountRepository` nhưng import/ném `AccountPersistenceException` và `DuplicateAccountException` từ `service` (`MySqlAccountRepository.java:10-15,27-50`).
- Do đó **CONFIRMED** package dependency cycle `service → repository → service`. Đây là design issue và maintainability coupling; chưa phải functional defect.

#### Cohesion/coupling khác

- **CONFIRMED** — service dùng trực tiếp request/response DTO; DTO lại dùng Jakarta Validation và JPA entity/enums (`FoodService.java:5-7`; `OrderService.java:5-11`; `FoodDto.java:3,10-12`; `OrderDto.java:3-6,18-26`). Thay đổi transport/persistence có thể lan vào business service.
- **CONFIRMED** — `common` không phải kernel thuần: `GlobalErrors` phụ thuộc Servlet, Spring Web và Spring DAO, trong khi `BusinessException` là business concern (`GlobalErrors.java:3-18`; `BusinessException.java:3-33`).
- **CONFIRMED** — `shared.api` chỉ có `AuthenticatedUser`/`Role`, nhỏ và cohesive (`AuthenticatedUser.java:5-9`; `Role.java:3`).
- **CONFIRMED** — `platform.security` giữ implementation BCrypt/JWT ngoài business ports; đây là điểm coupling được kiểm soát tốt (`BCryptPasswordHasher.java:5-15`; `LocalRsaTokenIssuer.java:12-37`).
- **POTENTIAL ISSUE** — concrete service-to-service dependencies làm unit test vẫn mock được bằng framework nhưng hạn chế substitution bằng interface/fake tự nhiên; impact thực tế cần xem test/code-change ở hạng mục phù hợp.

### 3.6. Error Handling Assessment

#### Exception flow hiện tại

1. Food/Cart/Order ném `BusinessException(type, code, message)`; `GlobalErrors` map INVALID/FORBIDDEN/NOT_FOUND/CONFLICT sang 400/403/404/409 (`BusinessException.java:3-33`; `GlobalErrors.java:24-32`).
2. Bean binding/type/media errors được global advice map sang contract HTTP; DAO integrity/locking exception được đổi thành 409; fallback `Exception` thành 500 (`GlobalErrors.java:35-80`).
3. Auth dùng `AuthFailure`, `DuplicateAccountException`, `AccountPersistenceException`; `AuthErrors` xử lý hai loại đầu, còn persistence failure rơi vào fallback 500 (`AuthErrors.java:17-36`; `AccountPersistenceException.java:3-4`).
4. Security filter chain và login IP filter tự viết response vì chạy trước MVC advice (`SecurityConfiguration.java:43-48`; `LoginIpFilter.java:14-20`).

#### Phát hiện

- **CONFIRMED** — business error mapping được tập trung và service không phụ thuộc HTTP status.
- **CONFIRMED** — `MySqlAccountRepository` phụ thuộc exception thuộc `service`, làm infrastructure error propagation tăng coupling ngược (`MySqlAccountRepository.java:10-11,27-50`).
- **POTENTIAL ISSUE** — duplicate detection phụ thuộc MySQL error code `1062`, constraint name và nội dung SQLException (`MySqlAccountRepository.java:45-48`); thay schema/vendor/driver message có thể đổi behavior. Chưa có failure evidence.
- **POTENTIAL ISSUE** — `GlobalErrors` vừa là HTTP mapper vừa hiểu Spring DAO exception, khiến API error policy biết persistence abstraction (`GlobalErrors.java:6-7,59-69`).
- **CONFIRMED** — unexpected exception không lộ message ra response; log giữ stack trace và client nhận generic `INTERNAL_ERROR` (`GlobalErrors.java:77-85`). Không đánh giá sâu logging/security trong hạng mục này.
- **PENDING** — chưa chạy test để xác minh mọi exception path và rollback thực tế.

### 3.7. Testability & Maintainability

#### Điểm hỗ trợ testability

- Service/controller dùng constructor injection hoặc Lombok `@RequiredArgsConstructor`; repository/ports có thể mock/fake (`RegisterService.java:17-19`; `LoginService.java:17-21`; `FoodService.java:19-26`; `CartService.java:21-26`; `OrderService.java:21-31`).
- `Clock` được inject vào Order/JWT/rate limiter, tránh hard-code thời gian (`AdapterConfiguration.java:20`; `OrderService.java:31`; `LocalRsaTokenIssuer.java:20`; `LoginRateLimiter.java:12-16`).
- `PasswordHasher` và `TokenIssuer` là interface với adapter riêng; Auth service có thể unit test không dùng crypto thật (`PasswordHasher.java:3-5`; `TokenIssuer.java:6-7`).
- Repository interfaces và service transaction boundary cho phép tách unit test với integration test ở mức thiết kế.

#### Hotspot maintainability/testability

- `OrderService` là hotspot chính do kích thước, fan-out và số nhóm rule; sửa checkout/state/listing có khả năng ảnh hưởng cùng class.
- `FoodService` kết hợp catalog và stock; `CartService` kết hợp aggregate mutation, response enrichment và checkout helpers.
- Service dùng concrete service khác và DTO/entity-backed types, làm test fixture và change impact rộng hơn các service chỉ dựa trên port.
- `AdapterConfiguration`, `SecurityConfiguration`, `LoginRateLimiter` có style nén nhiều statement/condition trên một dòng; **CONFIRMED code readability smell**, nhưng không có formatter/line-length criterion để kết luận vi phạm chuẩn (`AdapterConfiguration.java:20-52`; `SecurityConfiguration.java:19-49`; `LoginRateLimiter.java:6-27`).
- Static helper/mapping (`AuthValidation`, DTO `fromEntity`) dễ gọi trực tiếp nhưng không thay thế được qua dependency; đây là trade-off nhỏ, chưa có bằng chứng gây khó test.
- **PENDING** — tồn tại test source không đồng nghĩa test pass, coverage đủ hoặc hotspot được bao phủ; giới hạn hạng mục không cho chạy build/test.

### 3.9. Conclusions & Pending Questions

- **CONFIRMED** — duplication chủ yếu localized; một phần similarity trong error handling là do khác lifecycle filter/MVC, không nên gọi là duplication thuần túy.
- **PENDING** — metric heuristic không thay thế AST complexity tool; test/coverage/runtime behavior không được suy ra từ source.
